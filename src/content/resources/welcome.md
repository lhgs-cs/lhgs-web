## 这个板块收什么

你用过、觉得值得推荐给别人的东西：

- 网站、文档站（MDN、GitHub Skills 这类）
- 书，包括实体书和电子书
- 视频课程、公开课
- 工具、软件、插件
- 线下资源（图书馆、课程、讲座）

**不限于能点开的链接** —— 实体书、线下讲座都没法跳转，照样可以推荐。这正是这个板块用文章而不是链接列表的原因。

## 怎么投

在 `src/content/resources/` 下新建一个 `.md` 文件，**文件名就是网址**：

```
src/content/resources/pro-git.md
        ↓
https://lianhegongshe.cn/content/cs/resources/pro-git/
```

文件名用英文小写加短横线，别用中文和空格。

## 开头的 frontmatter

```markdown
---
title: Pro Git —— 唯一的 Git 官方书
description: 免费在线阅读，从基础命令到内部原理都有。
publishDate: 2026-10-22
tags: [工具, 书籍]
author: 你的名字
link: https://git-scm.com/book/zh/v2
pinned: false
---

正文从这里开始……
```

### 字段说明

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | ✅ | 资源名称，可以带上你的评价，如「《算法（第 4 版）》—— 适合啃的第一本算法书」 |
| `description` | ✅ | 一句话说明这是什么，列表页显示 |
| `publishDate` | ✅ | **必须 `年-月-日` 格式**，用来排序 |
| `tags` | ❌ | 数组，如 `[算法, 书籍]`。列表页可按它筛选 |
| `author` | ❌ | 署名，不写就不显示 |
| `link` | ❌ | 外部链接。**实体书、线下资源请直接删掉这行**，不要瞎填 |
| `pinned` | ❌ | 填 `true` 会置顶 |
| `draft` | ❌ | 填 `true` 变草稿 |

## 一篇合格的推荐应该写什么

这是本板块和"链接导航站"最大的区别。**只贴链接加一句"这个很好"，等于没写**。

至少覆盖这四点：

### 1. 这东西是干什么的

一句话说清。读者扫一眼就知道要不要继续看。

> MDN 是 Mozilla 维护的 Web 标准文档，HTML / CSS / JavaScript 的每个特性都有规范级说明。

### 2. 你为什么推荐它

它好在哪，和同类比强在哪。这是**最值钱**的部分 —— 别人搜不到，只有你知道。

> 搜到的博客经常是几年前的写法，MDN 会告诉你这个特性现在还能不能用。

### 3. 适合谁 / 不适合谁

比推荐理由更有用。一句话帮读者省下几小时。

> 适合已经会写代码、但没系统学过数据结构的人。完全没写过代码的人不适合，书里假设你能读懂 Java。

### 4. 怎么用最有效

你的真实使用经验，不是照抄官方介绍。

> 不要从头读到尾，遇到问题带着关键词去搜。每个页面右侧的"浏览器兼容性"表格是最有价值的部分之一。

### 加分项

- **获取成本**：免费 / 多少钱 / 图书馆能不能借到
- **配套资源**：有没有代码仓库、练习题、社区
- **你的使用时长**：用了多久，比"我觉得不错"可信得多

## 正文结构建议

不需要严格照搬，但这个顺序通常最好读：

```markdown
## 为什么推荐它
## 适合谁
## 不适合谁
## 怎么用
## 配套 / 获取方式（可选）
```

**标题从 `##` 开始**，`#` 留给页面标题。

## 提交

```bash
git add src/content/resources/你的文件名.md
git commit -m "docs: 新增资源推荐：xxx"
```

推到 `main` 后 GitHub Actions 会自动构建部署。

## 最后一句

推荐资源的门槛不是"这东西牛逼"，而是"**你能说清楚它为什么对别人有用**"。说不清就先别发，用一段时间再说。
